# dsh-git-push 代码质量分析报告

> **代码属他人**（作者 EIGHTfs）。本报告仅为**客观质量分析**，分析人不参与代码编写，不对代码缺陷承担任何责任。
> **交付说明**：本报告为独立分析文档，分析过程中**未修改**本仓库的任何代码或其他文档。

## 一、分析范围与方式

- **通读源码**：`lib/` 下全部模块——`core.js`(2714 行)、`index.js`(1237)、`audit.js`(637)、`client.js`(647)、`viewer.js`(638)、`viewer-locales.js`(117)、`permit.js`(132)、`rules.js`(143)、`quality.js`(259)、`repo-index.js`(285)、`env-inject.js`(222)、`llm.js`(81)，合计约 8100+ 行。
- **实测验证**：
  - 11 个 lib 文件 `node --check` 语法检查 **全部通过**。
  - 9 个测试 7 绿 2 红：`test-apply.mjs` 因缺 `@deepseek-ai/dsh-tools` 运行时依赖失败；`test-core.mjs` 因 `dsh-git-push-User` 处于只读卷（EROFS）失败。**均为环境问题，非代码 bug。**
- **交叉核验**：`docs/code-quality-checklist.yaml` 是**合法 YAML**（197 行，`safe_load` 干净解析），但 `scoring.dimensions_weight` 10 项全为空值。

## 三、主要不足（8 项，带行号证据）

### 🔴 1. 评分只算 4 个维度，其余 6 个硬编码（诚实性问题）
`lib/quality.js:228-242` 的 `scoreQuality()` 只真实计算 4 个维度（可读/健壮/性能/测试），其余 6 个（可维护/安全/可观测/可部署/文档/DX）**全部写死常量**（8/9/7/7/7/7）。所谓「0-100 评分」实际只衡量了 40% 的维度。`audit.js:602-609` 的 `qualityFindings` 过滤同样印证了这一点。

### 🔴 2. 评分标准 yaml：权重是空占位，与评分器解耦
- `docs/code-quality-checklist.yaml` 是**合法但有效**的标准文件（6 criteria + 3 additional + 10 checklist），其 `summary.level_definition`（A/B/C/D 等级描述）**被 quality.js 加载使用**。
- 但 `scoring.dimensions_weight`（`quality.js:59` 兜底前解析）10 个键**全为空值**，`quality.js` 始终回退到内置 `DEFAULT_WEIGHTS` → **yaml 的权重从未被用到**。
- 且该文件被 `.gitignore:22` 忽略（注释「YAML 非法」是误判），标准本身不进仓库、不随版本管理；即便以后填了权重，`quality.js` 也读不进去。

### 🟠 3. 两个巨型文件难维护
- `lib/core.js` 2714 行：纯函数合集，过长。`line 524` 风格不一致：`export function findGitDirs(root, depth = 3) {  let out = ''`（函数体挤同一行、双空格）。
- `lib/viewer.js`：浏览器 JS 是 **280 行内嵌 IIFE 字符串**（`VIEWER_SCRIPT`），全塞进模板，无法单测、难审查。数据层 `getCommitHistory` 有测试，但页面逻辑 `renderSidebar/buildCommit/loadDiff` **一行测试都没有**。

### 🟠 4. 死注释 / 重复 JSDoc
`core.js:1210-1216` 对 `collectRepoSkillDirs` 有**空 JSDoc + 两段重复注释**三块；`audit.js:63-64` 注释内有复制粘贴残留。这类空/重复注释是噪音，且插件注释里大量引用「用户要求/用户原话」原文，会被自己的 comment-wording 审计机制误伤。

### 🟠 5. 无工程工具链
- `package.json` 无 `dependencies`/`scripts`/`engines`/`license`，依赖全靠 harness 隐式提供。
- 无 ESLint/Prettier/`.editorconfig`，全仓风格不统一。
- 无覆盖率测量；README 让用户**手动逐个跑** 9 个测试，无聚合 runner。

### 🟡 6. 测试实际运行结果（本次实测）
```
PASS  test-audit / test-env-inject / test-permit / test-quality / test-repo-index / test-rules / test-viewer
FAIL  test-apply.mjs   → ERR_MODULE_NOT_FOUND @deepseek-ai/dsh-tools（缺运行时依赖）
FAIL  test-core.mjs    → EROFS 只读卷（dsh-git-push-User 本环境只读挂载）
```

### 🟡 7. 性能：环境探测开销
`env-inject.js` 的 `DEFAULT_TOOL_PROBES` 每次会话探测 14 个工具（`which` + 版本 = 最多 28 次子进程 spawn），仅 `index.js` 里 60s 缓存。对单会话无感，但属重复性子进程开销。

### 🟡 8. 硬编码默认 owner `EIGHTfs`
`autoTagDSHProject` / `remoteToRepoInfo` / `queryGitHubVisibility` 等大量函数默认 `owner = 'EIGHTfs'`。作为可复用插件应可配置，但这是作者个人插件，可接受。

## 四、亮点

- **健壮性 93**：几乎处处返回结构化 `{ok, error, reason}` 而非抛错；处理了 CIFS/只读卷/NAS、token 有效性校验、分支免疫（master/main）、空 blob、`maxBuffer` 128MB 等大量边界。
- **安全性 90**：所有 GitHub 请求强制 `api.github.com`（hostname 硬闸 + `redirect:manual` 不跟随 302 到 codeload）、token 永不回传明文、原子写文件、`chmod 600`、查看器 HTML 转义防 XSS、仓库参数精确匹配防任意路径。
- **文档 95**：39 个版本 changelog、架构/文件结构/API 表/注意事项/TODO 齐全，每个函数都有「为什么这样设计」的注释。
- **测试框架**：9 个 `node:test` 文件、零第三方依赖、纯函数可独立单测。

---

## 五、结论

综合加权 **81/100（B 级）**。工程扎实、文档顶级、健壮/安全突出；主要短板在**规模/可维护性**（两个巨型文件）、**工程工具链缺失**、以及**评分权重与标准 yaml 解耦**。
