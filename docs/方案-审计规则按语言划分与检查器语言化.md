# 方案：审计规则按语言划分 + 检查器语言化（Python 落地实例）

> 状态：已实施（2026-10-05，1.11.0 合并提交）。
> 来源：`审计规则-Python不适配-反馈.md`（2026-09-28 KToolBox 实测反馈：Python + TSX 混合项目
> 408 文件，code_audit 全量 3009 条问题中 2882 条来自 nodejs slot，评分失真 56/C）。
> 本方案 = 反馈改造建议的完整落地记录：文件类型识别路由 + 检查器 Python 化 +
> 规则集划分方法，**以 Python 为实例**，后续加 C/Java/Go 等语言可照此步骤扩展。

---

## 一、问题背景（反馈实测）

KToolBox（Python + React TSX 混合，408 文件）全量审计：
- 问题 3009 条：blocker 1041 / warning 1958——**2882 条来自 `nodejs` slot**
- 质量评分 56/C（实际该仓库 mypy strict + 覆盖率 85%，远高于此）
- 三类误报：① `.py` 枚举码/版本号被 `magic-number-smart` 当魔数；
  ② TSX 前端 i18n 键/路由路径被 `no-repeated-hardcoded-literals` 当硬编码；
  ③ docs 文档示例 token 被凭据扫描当真实泄露。

根因（反馈 §二）：
1. 规则按 slot 分桶，但 slot 对非 Node 语言**无降级/排除**——nodejs 规则对 .py/文档全跑
2. **无「文件类型识别」层**：规则集选择不感知语言/扩展名/目录语义

## 三、检查器语言化模式（核心方法论）

### 3.1 原则：检查器 = 语言无关核心 + 语言分支

现有检查器基于 **JS 语法特征**（`function` 关键字、`{` 大括号、`const/let/var`）。
Python 无这些（`def` + 缩进），直接复用必然全失效（实测 python.yml 6 条规则对 py
一条不命中）。语言化 = 在检查器内加 **Python 分支**，JS 路径不变（零回归）：

```js
// 通用模式：入口检测语言特征 → 分流
export function checkComplexityAst(text = '', opts) {
  if (pythonDetectDef(text)) return checkPythonComplexity(text, opts); // Python 分支
  // ...原有 JS token 级逻辑（不动）
}
```

### 3.2 Python 语法特征与对应检查器改造

| 检查器 | JS 语法依赖 | Python 替代 | 实现 |
|---|---|---|---|
| min-length（短名） | `function name(` / `const name =` | `def name(` / `name = 值` | token 流识别 def/等号前短 ident；**排除 const/let/var 前缀避免双报** |
| func-lines（函数长） | `function` + `{` 配对 | `def` + 缩进体 | `pythonFuncRanges(text)`：行级扫描 `def name(...):` → 缩进 > def 行缩进的行集合 |
| complexity（圈复杂度） | `if/for/while` token + `{` 块 | 行首控制流关键字（if/elif/else/for/while/try/except/with/assert）+ 行内 and/or | `checkPythonComplexity`：函数体内逐行计数 |
| nesting（嵌套深度） | `{` 块语句层级 | 缩进层级（每级 4 空格近似） | `checkPythonNesting`：BLOCK_LINE 行 +1，缩进回退 -1 |
| magic-number | `const NAME = num` 命名常量 | 同 + **枚举成员** + **全大写常量**（PEP8） | `collectPythonEnumAssignLines` + `isNamedConstantValue` 放宽全大写 |

### 3.3 Python 函数范围（pythonFuncRanges，各检查器共享）

Python 无大括号，函数体 = 缩进块。`pythonFuncRanges(text)` 返回
`[{startLine, endLine, len, name}]`（与 JS funcRangesAst 同构）：
- `def name(...):` 行 = 起点
- 后续「非空且缩进 ≤ def 缩进」的行 = 函数外（结束）；其间行 = 函数体
- 注释行（`#` 开头）不打断函数体；空行不打断

func-lines 已统一走 funcRangesAst（合并 JS + Python 双语言函数范围），
complexity/nesting 各自用 pythonFuncRanges + 行级统计。

### 3.4 双语言回归保障

所有语言化改造**必须双测**：
- Python 新功能生效（枚举豁免/短名/长函数/嵌套/复杂度各自用例）
- JS 旧行为不变（既有测试全绿——本项目 865 个测试锁死）

关键坑（已踩）：
- min-length 的 Python 分支若不过滤 const/let/var 前缀 → JS 的 `const c = 1` 被**二次报**
  （JS 分支 + Python 分支各报一次 → `声明 c 照报 2 !== 1`）
- i18n 键正则若过宽 → 域名 `api.example.com` 被当 i18n 键豁免（重复应报的漏报）
  → 加域名特征排除（`.com/.net/.example` 等词段）
- Python 复杂度 `def` 本身不计分支（基线 cx=1），与 JS「函数体不计深度」口径一致

## 四、规则集划分（文件类型识别路由）

### 4.1 机制：槽位动态发现 + exts 语言作用域

- 槽位 = `lib/audit-rules/audit-rules-<名>.yml`（**放文件即生效**，UI 规则包列表自动出现）
- 规则 `exts: ["py"]` = 只对 .py 生效（filterRulesByExt 消费）
- 同 kind 规则跨槽位 = 检查器跑一次（dispatch 按 kind 合并规则数组）→ 不双报

### 4.2 划分动作（Python 实例）

1. **新建 `audit-rules-python.yml`**：python/* 前缀规则，exts:["py"]：
   - `python/variable-min-length`（min_length: 2 → min-length kind）
   - `python/magic-number`（kind: magic-number-smart，枚举/全大写常量豁免）
   - `python/max-nesting-depth`（max_depth: 4 → max-depth kind）
   - `python/max-function-length`（max_lines: 50 → func-lines kind）
   - `python/max-file-length`（max_lines: 400 → max-lines kind）
   - `python/max-cyclomatic-complexity`（max_complexity: 15 → max-complexity kind）
2. **nodejs 让位**：6 条语言无关规则（variable-min-length/magic-number-smart/
   max-nesting-depth/max-function-length/max-file-length/io-risk）的 exts
   **移除 py/go/rs/java 等非 JS 语言**——nodejs 不再接管 .py（反馈验收标准）
3. **io-risk 特例**：AST 检查器是 JS/Node fs 语法特定（fs.xxx/require('node:fs')），
   Python 的 open/with 不识别——声明 py 是误导，exts 移除 py（Python 文件 I/O
   检测需新检查器，另行覆盖）

### 4.3 效果（混合项目实测）

修复后对同一混合项目（_enum.py + app.tsx + docs.md + nested.py）：
- 三类误报清零（枚举/i18n/文档凭据）
- .py 文件命中规则前缀 = `python`（nodejs 不再接管）
- 真实问题仍抓：max-file-length（421 行报）、max-nesting（4 层报）、
  complexity（8 复杂度报）、func-lines（60 行报）

## 五、扩展其他语言（C/Java/Go 参考步骤）

新增语言 L 的完整步骤（以 Python 为模板）：

1. **确认 tokenizer 支持**：`lib/ast/tokenizer.js` 能否解析 L 的语法
   （Python 的 class/def 是 ident + 冒号，token 流可解析；C/Java 的
   `{` 大括号天然兼容现有 JS 检查器，可能**无需语言化**）
2. **语言无关规则**（大括号语言 C/Java/Go/Rust）：现有检查器（complexity/nesting/
   func-lines）按 `{` 配对即可工作，**只需**：
   - 新建 `audit-rules-<lang>.yml`（lang/* 规则，exts:["c","h"] 或 ["java"]）
   - nodejs 对应规则 exts 移除该语言（让位）
3. **无大括号语言**（Python/YAML 式缩进/offside rule）：按 §3 语言化检查器
   - 新增 `pythonFuncRanges` 的等价物（缩进法函数范围）
   - min-length/func-lines/complexity/nesting 各加分支
4. **语言特定豁免**（照 Python 三件套）：
   - 枚举/常量：L 的常量定义形态（全大写惯例等）
   - 重复文本：L 的 i18n/路由形态（若存在）
   - 凭据文档示例：md 同行示例词豁免（语言无关，Python 已修）
5. **回归保障**：L 功能用例 + 既有 JS 测试全绿（865 基准）

### 5.1 语言无关 vs 语言特定（判定表）

| 规则 | JS | Python | C/Java/Go（大括号） |
|---|---|---|---|
| max-file-length | ✓ | ✓（已验） | ✓ 直接可用 |
| max-nesting-depth | ✓ | ✓（缩进法） | ✓ 直接可用 |
| max-function-length | ✓ | ✓（def+缩进） | ✓ 直接可用 |
| max-cyclomatic-complexity | ✓ | ✓（行级） | ✓ 直接可用 |
| magic-number | ✓ | ✓（枚举/全大写） | ✓ 直接可用（常量形式适配） |
| variable-min-length | ✓ | ✓（def/等号） | ✓ 直接可用 |
| io-risk | ✓（fs 语法） | ✗（需 Python I/O 检查器） | ✗（需各语言 I/O 检查器） |
| no-repeated-hardcoded-literals | ✓ | ✓（i18n/路由豁免） | ✓ 语言无关 |
