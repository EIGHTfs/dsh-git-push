# 功能：发布与工具链

> 面向使用者：讲清插件的提交推送、克隆、npm 发布、仓库索引与账号状态、文档生成脚本怎么用。
> 本文只覆盖 git / 发布 / 工具链侧；静态审计引擎见《功能-审计引擎》。

## 一句话

插件把「本地 git 操作 → 提交推送 → npm 发布」收成一条链：所有写操作有预演与确认门禁，凭据由插件托管，落盘状态统一收口，读状态走 HTTP 而不是前端快照。

## 一、提交与推送

`git_commit_push`（CLI `git-sluice commit`）一次调用 = 提交前门禁 → 有改动才 commit → 有可推内容才 push。零改动是**正常成功路径**，回执会说明「本次无新提交」；远端已最新则回执写明未推送。

- **预演**：`dryRun: true` 只报告计划步骤，不写盘、不提交。
- **结构化提交信息**：`messageItems` 数组（`{what, type, why, verify}`）比单串 message 更可追溯；单串偏长时回执会给 usageHint。
- **精确暂存**：`paths` 传相对路径时只 `git add` 指定文件，不把他人未提交改动扫入（默认 `git add -A`）。
- **门禁**：`requirementsConfirmed` 表示已核对开发者要求；`pushConfirmed` 是推送门禁放行位。提交前审计会拦 blocker（审计本身见《功能-审计引擎》）。
- **提交身份**：仓库已配则用；未配则用登录账号身份写入仓库局部配置。历史上非规范身份只报告不改历史，改写由 `git_identity_rewrite` 单独负责（默认 dry-run，真改先建备份并 force-with-lease 强推）。
- **钩子**：回执列出本次会触发的钩子；只有「可证明坏掉」（解释器不存在 / 引用不存在的机器路径）才注入 `LEFTHOOK=0`，正常钩子照跑。
- **推送通道**：自动判定 remote 归属与本机可用形态，优先 `ssh://git@ssh.github.com:443/...`；归属不符的 `origin` 绝不覆盖（改走 `github-ssh`）。`remote` 参数指定多 remote / fork 场景的目标，推送与核验使用同一 remote。
- **回执**：带本地 HEAD 与远端 HEAD 两个 sha、核验结论；`waitCi: true` 可按推到远端的 sha 等 GitHub Actions（默认不等，`ciTimeoutSec` 上限 900 秒），等待期间 job 显示运行中属预期。

`git_sluice`（CLI `git-sluice git`）透传任意 git 命令并自动注入凭据。需要凭据环境变量时用 `git_cred_env`，输出只有前缀不含明文。

### CIFS / 挂载盘建仓

在 SMB 挂载上 `git init` 会因 `chmod config.lock` 半途失败。建仓统一经 `lib/git/init-compat.js` 的 `ensureUsableLocalRepo`：检测残缺 `.git` 并修复，属主与进程 uid 不一致时把路径登记进 **global `safe.directory`**（仓库级 `[safe] directory` 不生效，所有权检查先于读仓库配置），注销时精确移除该条。`git_remote_create` 因此可在挂载盘上工作；`pushInitial: true` 先本地提交再走 Git Data API 上传，全程不依赖 `git remote add/config`。

## 二、克隆与远程仓库

- `git_clone`：走 GitHub Git Data API 重建真实提交历史（可推回远端）；`history: false` 退回整树快照。`git_clone_preview` 只探测不落盘。
- `git_remote_create`：按项目文件夹建远端仓库（缺省 private，`dryRun` 只探测预演，`pushInitial` 首次推送）。
- `git_remote_rename`：PATCH `/repos/{owner}/{repo}` 改仓库名，`dryRun` 默认开，报告旧名在 README/CI/文档里的出现位置（URL 与文字分开统计）；真改后同步本地 remote。改名不可逆，外部引用需自行更新。
- `git_set_visibility`：切换 public/private（改 public 前先确认无凭据/隐私）。
- **镜像选择**：`DSH_GIT_MIRROR_PREFIX` 显式值 > 出厂清单 `lib/core/mirror-candidates.json` 首个未停用候选 > 全停用则直连；停用判据是数据校验（声明总长 / blob sha 不符），连续 3 次停用、一次成功清零。`github_download` 下载 release/raw/源码包时自动轮换通道。
- `git_account_check`：token 在线校验 + SSH 公钥指纹，返回登录态/用户名/公钥数/套餐。

## 三、npm 发布与撤包

发布是**不可逆**操作，因此默认 dryRun：只做体检与 `npm publish --dry-run`，不写 registry；真发必须同时 `confirm: true` 且 `dryRun: false`。

```
git-sluice npm-publish [目录] [--dry-run|--no-dry-run] [--tag <tag>] [--otp <码>] [--confirm] [--json]
```

- **前置体检**：`private:true` 拦截、同名版本占用检测（不可覆盖）、`npm pack` 文件清单与体积。
- **发布前冒烟**：`npm pack` → 干净目录 `npm i <tgz>` → 按 `exports` 公开面逐个 import → 校验 dependencies 已装入；失败即拦（`blocked: smoke-failed`）。按包形态验证：有库入口验 import，只有 bin 跑 `--version` + `--help`，两者皆无明确报「没有可验证入口」。
- **本地 registry 彩排**（`localPreview: true`）：真实 publish 到本机 registry 再安装加载公开面，不写公共 registry；`scripts/local-registry.mjs --selftest` 可单独自检。
- **凭据**：由插件托管（配置目录 `config.json` 的 `npmToken`），发布时自动注入 0600 npmrc；无需 `npm login`，也不向用户索要 token。缺凭据直接报错，不静默降级到匿名。
- **撤包**：`npm_unpublish` 默认 dryRun 预检（版本存在 / dist-tag 指向 / 72h 窗口 / 唯一版本冷却），真撤需 `confirm:true`；超 72h 只有满足「无依赖者+周下载<300+单一维护者」才允许，否则改用 `deprecate`。
- **发布后核验**：`npm view <name>@<version> version` 与 `dist-tags` 才是正确判据。裸 curl 会命中 CDN 缓存给出陈旧结果（版本暂不可见属正常延迟，不是失败）。
- **子路径导出**：`package.json` 的 `exports` 暴露 `./audit`（`lib/audit/public.js`，稳定 API 门面）与 `./core`；`./client` 是浏览器端入口，不参与 Node import 冒烟。审计模块的边界由 `test/test-audit-git-boundary.mjs` 门禁（禁止依赖宿主运行时、插件装配层与仓库脚本）。

`npm_publish` 与 `npm_unpublish` 都注册为宿主后台 job，`job_output` 取结果。

## 四、仓库索引与账号状态

两份落盘数据，**唯一写入时机 + 唯一读取入口**：

| 文件 | 内容 | 写入时机 |
|---|---|---|
| `dsh-repo-index.jsonl` | 工作区 git 仓库索引（分支/remote/未提交/未推送/最近活动，JSONL 每行一仓；旧 `dsh-repo-index.json` 只读兼容并自动迁移） | 扫描/刷新；推送成功后先全量重建再精确回写 |
| `account-status.json` | token 与 SSH 公钥有效性快照（`valid` / `login` / `checkedAt`）+ API 配额 | 每次推送/提交验证账号时刷新；侧边栏打开只读 |

- `git_scan` 扫描工作区仓库；`scan-live.json` 暴露进度；落盘一律原子写（`.tmp` + rename），防写一半被读到。
- 索引只收「有 GitHub remote 且 owner 与登录账号一致」的仓库，无 remote 的本地仓归入 `localOnly`。
- 写接口返回 `indexUpdated` / `statusUpdated` 标志，UI 据此重新读取，避免「写了但界面没变」。
- 「校验于 <时间>」停在很久以前，通常意味着此后没有成功的推送，不是功能坏了；点侧边栏「重新检测」或成功推送一次即可刷新。
- 凭据真源（token / SSH 私钥）与这两份**状态快照**是两回事：「是否已配置」一律查凭据真源，不看快照。
- 数据都在 `<DSH_HOME>/git-push/`，不要手工改。

`git_api` 直接调用插件 36 条 HTTP API（与浏览器/CLI 同源 `handleHttp` 路径）；`git_scan` / `io_scan` / `scope_check` / `module_splitter` / `link_check` 等辅助工具见 `docs/SPEC.md` 工具表。

## 五、文档生成与结构追踪

三份产物由脚本从**真实代码与 git 历史**生成，并有测试盯着「文档与真实状态是否一致」——不是手写的，改完代码跑一条命令即可对齐：

```
node scripts/doc-tree.mjs    gen|apply|check     # README 目录结构块
node scripts/doc-func.mjs    gen|apply|check     # docs/FUNCTIONS.md
node scripts/doc-version.mjs gen|apply|check     # docs/CHANGELOG.md
```

- `apply` 写盘；`check` 有漂移即非零退出（CI 与提交门禁消费）。
- `doc-tree.mjs sync` 对齐 `tree-doc.json` 的键集合与真实文件：新增文件补键并标「（待注释）」，删除文件清掉失效键；`_meta.worktree` 单独记录未提交变动文件及修改时间，提示该条目的注释可能需更新，不污染描述文本、不进 README。
- `tree-doc.json` 是「路径 → 一句话介绍」映射，目录结构块每行介绍取自它。新增重要文件时顺手补一句介绍。
- `doc-version` 的版本表来自**提交信息**：提交信息里写了版本号，版本表才多一行，所以发版提交的信息要带版本。
- 三份产物都是生成物，不要手改；`check` 失败不是「文档错了」，是「文档没跟上真实状态」，跑 `apply` 即可。

## 六、版本纪律

- 三处版本号一致：`lib/self/index.js` 的 `VERSION` ≡ `package.json` 的 `version` ≡ 版本表（`scripts/scan-version.mjs` 门禁）。
- 每次提交默认第三位（patch）+1；纯优化不升版本，改为多次本地提交建立暂存点，收尾压缩成一次推送。
- 0.x 是合法开发期，1.0.0 是稳定线（SemVer 2.0.0 §4）；禁止把 0.x 当「不合规」强制修正。权威口径见 `skills/workflow/versioning-rule.md`。
- 发版在 `version-metrics.json` 补量化对比，版本表会带上。

## 边界与注意

- 所有破坏性操作（推送 / 撤包 / 仓库改名 / 身份改写 / 切换可见性）都有 dryRun 或 confirm 前置。
- 推送回执「已推送」不等于已落地——用 `git ls-remote` 或匿名 API 独立核验远端 sha。
- 本机推送通道的实测事实（github.com:443 直连不通、api.github.com 通、ssh.github.com:443 通）见 `skills/ops-self-bootstrap-运维自举/push-channel-facts.md` 同名权威 skill；遇推送失败先实测通道再下结论。
- 仓库级 `[safe] directory` 对 dubious ownership 无效，必须用 global 配置；`init-compat` 已处理，手工排查时别再踩。
