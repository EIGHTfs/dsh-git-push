> **分析日期**：2026-09-09
> **分析方法**：独立实测——运行测试/CLI/审计工具、逐文件读关键模块、grep 统计代码模式，每条结论均附实测证据（命令/行号/输出），不参考 docs/ 内既有分析文档。

## 总评

工程质量整体高于平均水准：模块拆分清晰（v1.42.0 门面 + 11 个功能模块）、注释密度高、规则引擎插件化设计合理、12 套测试显式 glob 运行全部通过。**但存在 4 个「现在就会坏」的确定性缺陷（P0），以及同步 IO 阻塞、测试覆盖断层、HTTP 端点无鉴权三个结构性短板（P1）。** 讽刺的是，其中两项（js-yaml 未声明、license 缺失）正是本项目自家 npm 审计规则要拦的问题——「审计别人很严，修自己拖延」。

## 一、P0：当前已坏的确定性问题（实测复现）

### P0-1 js-yaml 幽灵依赖——npm 包发布即崩

**证据**：
- `lib/audit.js:23`、`lib/rule-packs.js:36`、`lib/readme-gen.js:10` 三处静态 `import { load } from 'js-yaml'`
- package.json **没有 dependencies 段**，只有 peerDependencies（@deepseek-ai/dsh-tools、dsh-llm、schemastery）
- 实测解析路径：js-yaml 实际来自主仓 `node_modules/.pnpm/js-yaml@4.2.0`——被 pnpm 提升借用，本仓内 `ls node_modules` 为空

**后果**：
1. 用户 `npm install dsh-git-push` 后，任何入口（含 `lib/index.js`、`cli.mjs`）一加载就 `ERR_MODULE_NOT_FOUND`，插件整体不可用，不是降级而是崩溃——静态 import 无法走「js-yaml 缺失回退 heuristic 模式」的兜底逻辑（兜底只在运行时 catch 里，import 失败在模块加载期）。
2. `cli.mjs:7` 帮助文本自称「零第三方依赖；Node ≥18」——**不实**。cli.mjs → lib/core.js → lib/audit.js → js-yaml，链条上必然需要 js-yaml。独立环境跑 `git-sluice` 直接崩。
3. README v1.51.0 版本表自己写了审计规则要拦「js-yaml 未声明」，且 `audit-rules-npm.yml` 里有对应规则——规则在，问题一直没修。

**修复**：package.json 加 `"dependencies": { "js-yaml": "^4.1.0" }`（peerDeps 保持）；cli.mjs 注释改为「仅 js-yaml 一个第三方依赖」。

### P0-2 `npm test` 直接失败

**实测**（Node v24.19.0）：
```
$ npm test
Error: Cannot find module '/…/dsh-git-push/test'
✖ test (55.899412ms) — 'test failed'
```
package.json `"test": "node --test test/"`——目录参数在当前 Node 版本下没有解析到 `test-*.mjs`（默认发现模式不匹配 `test-` 前缀命名）。显式 glob 才能跑：
```
$ node --test test/*.mjs   # 12 个套件全部通过
```
**后果**：新环境/CI 里 `npm test` 永远红，README 声称的「全量回归 476/0」实际是手动跑 glob 的结果，脚本不可复现。若上了 CI（当前没有），第一个红的就是它。

**修复**：`"test": "node --test test/*.mjs"`，并新增 `test-*.mjs` 到 Node 发现模式的兼容考虑（或改名为 `*.test.mjs`）。

### P0-3 CLI `--depth` 参数：帮助文本承诺、实现缺失

**实测**：
```
$ node cli.mjs scan --depth 2 /tmp
未知参数: --depth
```
- cli.mjs:60 帮助文本写明 `scan [root] [--depth N]`
- cli.mjs:32-50 `parseArgv` 白名单里没有 `--depth`，走到 `a.startsWith('--')` → 报未知参数退出
- cli.mjs:169 `cmdScan` 里 `Number(flags.depth)` 永远是 undefined → 恒用默认 3

**后果**：功能虚假宣传 + 用户显式参数被拒。test-cli.mjs 未覆盖 --depth（grep 零命中），测试也没兜住。

**修复**：parseArgv 加 `else if (a === '--depth') flags.depth = argv[++i];`，test-cli 补断言。

### P0-4 自家审计规则拦自家文档——两份文档在工作区挂起无法提交

**实测**：`code_audit`（本仓）返回 **blocked: true，6 个 blocker**，全部是 `docs-conversation` 规则命中 `docs/DESIGN-2026-09-09-unified-rule-loader.md`（291 行，6 处命中）。`git status` 显示该文档 + `docs/code-analysis-2026-09-09.md` 均为未跟踪状态（stat 实测创建于 2026-09-09 晚间 22:52 / 23:11）——文档刚落盘就发现被自家门禁拦死（blocker 6），提交流程无法走通。

**后果**：不是规则错了（措辞规范本身合理），而是**流程缺一环**：文档措辞改写/移入 `data/沟通文档` 没有形成习惯或自动化提示闭环，产出物积压在工作区。

**修复**：短期处理积压文档（改写为中性技术描述或移入豁免目录）；长期在 code_audit 拦截输出里给出「一键改写建议」或提供 `data/沟通文档` 自动迁移路径。

## 二、P1：结构性短板

### P1-1 同步 IO + spawnSync 贯穿 HTTP 请求路径——单请求阻塞全 GUI

**实测统计**：
- 同步 fs 调用 **130 处**（readFileSync 41 / existsSync 39 / readdirSync 14 / writeFileSync 11 / mkdirSync 10 / statSync 8 / chmod 4 / rename 2 / rm 1），覆盖全部 34 个 lib 文件
- `spawnSync` 9 个文件（git-core / github-api / remote-repo / token-credentials / repo-scan / audit / full-scan / env-inject / viewer）
- `gitRaw`（git-core.js:101）单次 git 超时 **600 秒**、maxBuffer **128MB**；`runGit` 120 秒

**后果**：plugin-http.js 的 `/api/git-push/audit`、`/full-scan`、`/scan`、`/rebuild`、`/commit` 全部同步执行（底层 spawnSync + readFileSync）。DSH webServer 与插件同进程——小仓增量审计实测仅 0.13s（cli.mjs audit 本仓）无感，但**重路径全是同步长任务**：full-scan 全仓读文件、`cloneViaApi` 逐 blob 拉取、`runGit`/`gitRaw` 的超时上限分别为 120s/600s（git-core.js:78/107）——任何一个慢 git 命令或大仓扫描都会**冻结整个 GUI、所有其他插件、所有 agent 会话的事件循环，最坏可达分钟级**。

**定位**：这是架构级短板，v1.42.0 拆文件没拆同步模型。修复成本高（async 化牵一发动全身），但至少应：① 把 audit/full-scan/scan 三个重路由改为 worker_threads 或子进程池；② HTTP handler 层加并发互斥，避免两个审计请求叠加。

### P1-2 HTTP API 写操作端点无鉴权

**证据**（plugin-http.js:306-361）：`/api/git-push/*` 直接注册到 DSH webServer，无任何 token/session 校验、无 Origin/CSRF 检查。其中**写操作端点**：
- `POST /commit`（提交+推送任意扫描范围内仓库）
- `POST /rebuild`（**重建 git 历史**，force 时覆盖远端）
- `POST /remote-create`（在 GitHub 上创建仓库）
- `POST /gen-ssh-key`（生成 SSH 密钥对，force 时备份覆盖旧钥）
- `POST /permit/config`（开关自动推送）

**风险定性**：浏览器里任意网页可向 `http://127.0.0.1:<port>/api/git-push/rebuild` 发跨站 POST（fetch/no-cors 或表单），DSH 端口若监听 0.0.0.0 则扩大为局域网暴露。审计/读类端点泄露仓库列表与提交历史同样无门。

**修复**：① 校验 `Origin`/`Host` 头（拒绝非本机来源）；② 或要求 POST 带 `X-DSH-CSRF` 自定义头（跨站表单无法伪造自定义头）；③ 至少对 rebuild/gen-ssh-key/commit 三个高危端点加确认参数。

### P1-3 测试覆盖断层：插件接线层 1606 行零测试

**实测**（grep test/*.mjs 的 import 映射）：
- 35 个 lib 文件中 **22 个没有任何测试文件直接 import**
- 其中引擎核心部分（audit/rule-packs/quality/full-scan/core 门面）有直接覆盖，commit-push/github-api/token-credentials 经 core.js 门面被 test-core 间接覆盖
- **完全零覆盖的重灾区**：plugin-http.js（361 行，全部 HTTP 路由）、plugin-tools.js（383 行，11 个 agent 工具注册）、plugin-setup.js（202 行，配置解析+设置 watch）、plugin-commit-flow.js、plugin-push-permit.js、client.js（1039 行 UI）、llm.js、env-inject.js 的注入格式、version-history.js（rebuildHistory 破坏性操作！）、remote-repo.js（创建远程仓库）、workspace-context.js、readme-gen.js、ignore-scan.js 的部分函数

**后果**：恰好是「破坏性最强、外部交互最多」的层（重建历史/推远端/写凭据/HTTP 面）没有回归保护。v1.60.0 刚对 plugin-http 做过大重构（注册函数 362 行拆 handler），靠的是「行为零变化」的人工核对而非测试。

**修复优先序**：version-history（rebuildHistory 有 backup tag 逻辑）→ plugin-http（路由 405/404/参数校验）→ plugin-commit-flow（门禁分支）→ plugin-setup（watch 覆盖链）。

### P1-4 静默 catch：175 处 catch 中 21 处无日志吞错

**实测**（`catch { /* 注释 */ }` 形态，部分清单）：
- repo-index.js ×5、workspace-context.js ×5、audit.js ×8、rules.js:127、remote-repo.js:178、commit-push.js:89 等
- 全部有中文注释说明意图（「读不到跳过」「坏 JSON 忽略」），但**全部无 log 输出**

**典型风险场景**：rules.js:127——用户在设置里填了 `commentWordingRulesFile` 路径，文件读不到时静默回退内置规则。plugin-setup.js:99 的上游调用方有 log.warn，但 workspace-context/repo-index 里的同类失败（读 skill 清单失败、读 repo-index JSON 失败）完全无声——上下文注入悄悄变空，AI 会话拿到残缺信息却无人察觉。

**修复**：低成本的改法是给这些 catch 统一加 `log.debug`（不吵但可排查）；凭据/规则/注入三类路径的失败至少 log.warn。

### P1-5 超大文件与超大函数——度量已知、整改未完

**实测**：
- audit.js **1066 行**（自家 fileLinesBase=200 基准的 5 倍）、client.js **1039 行**、rule-packs.js 660 行、viewer.js 652 行
- WORKBOARD-2026-09-09 自己列的未完成项：plugin-tools 12 工具抽独立函数、plugin-context-inject/push-permit 降到 <100 行、warning 级函数 10+ 个——**全部未勾选**
- 自评 61→77 分（B 级）是拆了 plugin-http/audit 调度后的成绩，距 B→A 的结构整改还有一整批 backlog

**附带问题——正则应试化**：client.js:2-4 注释自述「参数去括号（require => 单参箭头不匹配函数行数计数的 fnStart 正则）……纯语法等价改写」。这是**把代码写法迁就自家正则度量**——fnStart（quality.js:108）识别不了 `(require => {...})` 形态，就改写代码让度量好看。度量驱动改写语法而非重构结构，方向存疑；正确方向是把函数计数换成 AST 解析。

## 三、P2：工程卫生问题

### P2-1 package.json 发布元数据缺失

实测：`license` ❌、`repository` ❌、`author` ❌、`keywords` ❌、`dependencies` ❌。作为 npm 发布的包（bin: git-sluice），缺 license 视为「无许可」法律上不可复用；repository 缺失导致 npm 页面无源码链接。自家 audit-rules-npm.yml 的「license 缺失 / repository 建议」规则若扫自己就会命中。

### P2-2 无 CI、无 lint、无 LICENSE 文件

实测：`.github/`、`.eslintrc*`、`eslint.config*`、`LICENSE`、`tsconfig.json` 全部不存在。质量保障完全依赖：手跑测试 + 自家审计工具 + 人肉 README 版本表。至少应有 GitHub Actions 跑 `npm test` + `npm run check`，避免 P0-2 这类「脚本坏了没人发现」。

### P2-3 `check` 脚本覆盖 11/35 文件

package.json scripts.check 硬编码 11 个文件名，**漏掉 24 个**（含全部 plugin-*.js、git-core.js、rule-packs.js、cli.mjs）。应改为 `for f in lib/*.js cli.mjs; do node --check $f; done` 或 glob。

### P2-4 docs/1.js 杂物入库

`git ls-files` 确认 `docs/1.js`（77 行「代码质量检查工具单文件版」）被 git 跟踪——一次性演示脚本，文件名无意义，与 docs/ 其余文档性质不符。应删除或移出仓库。

### P2-5 测试框架双轨制

14 个测试文件：2 个用 `node:test`（test-env-inject、test-rules），12 个手写 `console.log + pass/fail 计数器`。手写版有 `process.exit(fail ? 1 : 0)` 兜底退出码（实测确认），但 node --test 汇总只统计 node:test 声明的 37 个顶层 test，手写的 400+ 断言在汇总里隐形，失败时只能靠翻日志找 ❌ 行。建议统一迁到 node:test 的 `t.test()` 子测试。

### P2-6 版本号三处维护

package.json 1.60.0 / cli.mjs:29 `VERSION = '1.60.0'` 手工同步（实测当前一致）；plugin-config.js 动态读包没错。已有 scan-version.mjs 自检脚本，但它是「事后检查」而非「单一事实源」。cli.mjs 可改为动态读 package.json。

### P2-7 .git/config origin URL 内嵌明文 token

实测：`git remote -v` 输出 `https://ghp_enD1Ar…@github.com/EIGHTfs/dsh-git-push.git`——**真实 PAT 明文在本地 .git/config**。不入库（远端历史已验证干净，入库文件里的 token 全为占位假值），但任何能读仓库目录的进程、以及打印 remote URL 的工具输出（包括本插件 git_scan 回传的 remote 字段、会话上下文注入）都会带出该 token。与本项目「凭据收敛插件配置目录」的自家理念相悖。建议 origin 改为 SSH remote（github-ssh 已配置好）或 `git config credential.helper`。

### P2-8 README 巨型单文件

README.md 实测 66737 字节 / 219 行，版本表 76 条目（v1.1.0 起）全部平铺且单条动辄上千字（v1.54.0 一条约 1200 字）。修复指引（P0-1 js-yaml）埋在 v1.51.0 的长段落里根本没人翻到。建议：版本表拆 HISTORY.md（README 只留最近 3~5 条 + 指向链接），主体保留安装/用法/配置三件事。

### P2-9 skip-sensitive 豁免标记的盲区扩大

test-audit.mjs 等文件头带 `dsh-skip-sensitive` 标记（自身豁免审计），设计上合理（测试文件含检测目标措辞/token 样本），但意味着**这些文件从此对自己家所有审计规则永久免疫**——将来真有人往测试文件里写真实凭据或坏代码，门禁不响。建议豁免粒度按行/按规则，而非整文件。
