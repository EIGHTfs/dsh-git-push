# 单一真源与文档漂移治理方案（含本次已发现的分叉清单）

> 本方案为设计草案，**未修改任何代码**；审核确认后再按第七节看板执行。
> 触发：用户指出「git log 与 package.json 已分叉——新版认 npm 项目读 package.json，却残留旧的 git log 读法」，
> 并要求排查同类「没统一 / 文档与实际不一致」的位置，给出**一改全改**（单一真源）的做法。

---

## 一、修改目标

- **问题描述**：同一事实（版本号、规则包数、规则条数、工具数、设置键数、方法清单、文件树统计）在**多个位置各存一份**，
  改一处不会带动其它位置 ⇒ 出现"代码已改、文档还写旧的"分叉；本次已实测到多处。
- **期望效果**：每类事实**只有一个权威源**；其它出现位置要么由脚本**生成**，要么由门禁**校验**；不一致时**提交被拒**。
- **成功标准**：
  1. 新增 `scripts/doc-drift.mjs`（或并入 `doc-version.mjs`）能一次性列出所有分叉，退出码非 0；
  2. 接入 `npm test`（或 `npm run check:drift`），本地提交前必跑；
  3. 用本方案执行后，同一命令对两个仓库输出「一致」（0 处分叉）；
  4. 反向验证：人为把 README 的某计数改错，命令必须报错（阳性对照）。

## 二、潜在问题分析

| 风险类型 | 可能性 | 影响 | 缓解措施 |
|----------|--------|------|----------|
| 误报卡门禁 | 高 | 正常提交被拦，影响干活 | 计数类先只报 warning；blocker 只留给"版本三处不一致" |
| 生成覆盖手写内容 | 中 | 文档被脚本改坏 | 一律先 `--dry-run`（`doc-version apply --dry-run` 已是此模式） |
| 兼容性破坏 | 低 | 旧引用失效 | 保留 `doc-version gen/apply/check` 现有语义 |
| 维护成本转移 | 中 | 校验脚本本身也要维护 | 校验规则集中在**一个文件**，且规则数越少越好 |
| 数据丢失 | 低 | 无写操作（只读校验） | 校验脚本默认不写盘 |

**边界条件检查**：① 目录为空/文件缺失时校验脚本应报"无法校验"而非崩溃；② git log 不可读时不得把"读不到"当"没有"（本次事故）；
③ 同一数字在文档里出现多次（README 有 5 处写"14 个规则包"）⇒ 校验需覆盖**全部出现处**，不能只查第一处；
④ 数字与清单混排（"21 个规则槽位 / 124 条规则"）⇒ 需分别校验。

## 五、逐文件改动详情（执行阶段）

### 5.1 `scripts/doc-drift.mjs`（新增，唯一新增文件）
- **职责**：只读校验，输出分叉清单，退出码非 0 表示有分叉。检查项：
  1. `package.json.version` === `lib/self/index.js` 的 `VERSION`（blocker）；
  2. README 里所有 `<N> 个规则包/槽位` 与 `lib/audit-rules/*.yml` 文件数一致；
  3. 文档里所有 `<N> 条规则` 与 yml 内 `- id:` 计数一致；
  4. `<N> 个工具` 与代码内工具注册表条数一致；
  5. （插件仓库版）`package.json.version` === README 版本表首行 === skill 版本声明。
- **约束**：默认**不写盘**；支持 `--json` 供门禁消费；数字对不上时列出**文件:行号**。

### 5.2 `package.json`（两仓库）
- **改动**：加 `"check:drift": "node scripts/doc-drift.mjs"`，并挂进现有 `test` 脚本链。

### 5.3 `README.md`（dsh-git-push）
- **改动**：把 5 处手写"14 个规则包"改为**生成标记块**（复用 `applyVersionBlock` 同款机制）或改为准确数字；
  优先"生成"，避免下次再漂。

### 5.4 `docs/功能-审计规则体系.md`
- **改动**：条数改由脚本注入（`<!-- dshgp-rules:start -->` 标记块），不再手写。

### 5.5 `scripts/doc-version.mjs`
- **改动**：修正第 3 行注释为"版本号以 package.json 为准；历史行内容来自 git log"（消除文档与实现矛盾）。
