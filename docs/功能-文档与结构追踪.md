# 功能：文档与结构追踪（tree-doc / doc-func / doc-version）

> 面向使用者：讲清「仓库里那三份自动生成的文档是什么、怎么更新、漂移了怎么办」。

## 一句话

三份文档由脚本从**真实代码与 git 历史**生成，并有测试盯着「文档与真实状态是否一致」——它们不是手写的，改完代码跑一条命令即可对齐。

| 产物 | 生成脚本 | 内容 | 对应测试 |
|------|----------|------|----------|
| `README.md` 的目录结构块 | `scripts/doc-tree.mjs` | 真实目录树 + 每个条目一句话介绍（来自 `tree-doc.json` 映射） | `test/test-tree-doc.mjs` |
| `docs/FUNCTIONS.md` | `scripts/doc-func.mjs` | 扫描 `lib/` `scripts/` `test/` 的函数列表 | `test/test-doc-func.mjs` |
| `docs/CHANGELOG.md` | `scripts/doc-version.mjs` | 从 git log 聚合的版本表 | `test/test-doc-version.mjs` |

## 怎么用

三个脚本都是同一套子命令：

```bash
node scripts/doc-tree.mjs   gen|apply|check     # gen=打印 / apply=写盘 / check=查漂移
node scripts/doc-func.mjs   gen|apply|check
node scripts/doc-version.mjs gen|apply|check
```

- 改完代码或加了文件：跑 `apply` 写盘；
- CI / 本地自检：跑 `check`，有漂移就非零退出（我们的测试直接调它）。

`doc-tree.mjs` 的 `sync` 是 `apply` 的补充：它对齐 `tree-doc.json` 的键集合与真实文件——**新增文件会补进映射并标「（待注释）」**，删除文件会把失效键清掉。

## tree-doc.json 是什么

「路径 → 一句话介绍」的映射表。目录结构块里的每行介绍都取自它；没有映射的路径显示「（待注释）」，提醒你补一句。所以新增重要文件时，除了跑 `apply`，最好顺手在 `tree-doc.json` 里给它写一句介绍。

## 边界与注意

- 三份产物都是**生成物**：不要手改，改了会被下一次 `apply` 覆盖、也会被 `check` 判为漂移。
- `doc-version` 的版本表来自**提交信息**：提交信息里写了版本号，版本表才会多一行。所以发版提交的信息要带版本（如 `feat: 2.4.1 — …`）。
- `check` 失败不是「文档错了」，而是「文档没跟上真实状态」——跑 `apply` 即可。
