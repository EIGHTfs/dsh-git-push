## 二、确认的 Bug（实测/代码证据确凿）

### B1. `npm test` 在 Node 24 下直接失败
- **位置**：`package.json` scripts.test = `node --test test/`
- **实测**：Node v24 把 `test/` 当模块解析 → `Cannot find module .../test`，退出非零。
- **修复**：改 `node --test test/*.mjs`（实测此写法 36/36 通过）或 `node --test "test/"` glob 形式。

### B2. js-yaml 依赖未声明，裸装即崩
- **位置**：`lib/audit.js:23`、`lib/rule-packs.js:36`、`lib/readme-gen.js` 均 `import { load } from 'js-yaml'`，但 `package.json` **没有 dependencies 字段**，只有 peerDependencies。
- **实测**：本机 `import('js-yaml')` 能解析纯属 DSH 宿主 node_modules 碰巧 hoist；干净环境 `npm install` 后插件 ESM 加载即 `ERR_MODULE_NOT_FOUND`。
- **修复**：`dependencies: { "js-yaml": "^4" }`。

### B3. cli.mjs `scan` 命令字段名写错，永远显示 `-`
- **位置**：`cli.mjs:104` —— `r.dirty ?? r.uncommitted ?? '-'`
- **证据**：`repo-scan.js` `readRepoStatus` 返回的字段叫 `changes`，不存在 dirty/uncommitted。
- **影响**：CLI 的 scan 子命令「未提交数」列恒为 `-`，功能形同虚设。

### B4. findings 行号是「diff 内序号」不是文件行号
- **位置**：`audit.js` `lineNumber(file, idx) { return idx + 1; }`（注释自认「非精确」）。
- **影响**：secret/wording/docs-conversation 等所有新增行规则报出的行号全部偏移（多 hunk 文件错得更离谱），用户按行号去找会找不到。diff 解析时 `@@ -a,b +c,d @@` 的 c/d 被 `parseDiff` 丢弃了。

### B5. sync-in-async 规则对主流写法零检出
- **位置**：`quality.js:184` 只匹配 `fs.readFileSync(` 这种带 `fs.` 前缀的调用。
- **证据**：本仓库自己全部用裸导入（`import { readFileSync } from 'node:fs'`）——规则对本仓库 100% 漏检。即「性能维度」评分在实际代码风格下永远满分，评分虚高。
- **同类问题**：`checkSilentCatch` 只覆盖 catch 行 + 下一行两种形态，多行空 catch（第三行才闭合）漏检。

### B6. rebuild 中途失败不回滚，留半成品 orphan 分支
- **位置**：`version-history.js` `rebuildHistorySelective` / `rebuildHistoryFresh` —— orphan checkout 后逐组 commit，任何一步失败直接 return，仓库停留在 `rebuild-tmp`/`rebuild-fresh` 分支上，原分支引用未恢复。虽有 backup tag 兜底，但用户要自己手工 `checkout` 回来。
- **修复**：失败路径统一 `runGit(['checkout', branch])` + `branch -D rebuild-tmp`。

### B7. parseDiff 无法解析带空格/引号的文件名
- **位置**：`repo-scan.js:127` `diff --git a/(.*?) b/(.*)$` —— git 对含空格/中文路径输出 `a/"path with space"` 带引号形态，正则取到的 path 带引号或截断，后续 `join(repoPath, file.path)` 读文件失败 → 该文件审计被静默跳过。

### B8. cli.mjs VERSION 硬编码，与 package.json 手工同步
- **位置**：`cli.mjs:29` `const VERSION = '1.60.1'`。`scan-version.mjs` 的存在本身就是为了补这个洞。应改为运行时读 `package.json`（`plugin-config.js` 里已有同样写法可复用）。

### B9. docs/1.js 误入库
- 一个与插件无关的「单文件代码质量检查工具」脚本躺在 docs/ 下，明显是历史遗留垃圾文件。

## 三、设计性不足（非 bug 但值得修）

### D1. 同一文件重复读盘 6+ 次（性能）
`buildAuditContext` 已读过一次文件头，但 `checkMaxLinesRule` / `checkMaxDepthRule` / `checkMinOccurrencesRule` / `checkRepeatedString` / `checkCodeQuality` / `scoreFileIfReadable` 各自再 `readFileSync(fullPath)` 一次。一个文件一次审计最多读盘 7 次。应把 `fileText` 放进共享上下文复用。

### D2. 质量评分「名义 10 维，实测 3 维」
`scoreQuality` 里安全性=9、可观测性=7、可部署性=7、文档=7、开发者体验=7 全部写死。代码里自己标注了 scoringBasis，但对使用者展示的 A-D 等级容易被误读为「全面评估」。而且真正可测的 3 个维度中 sync-in-async 还是漏检的（B5）——实际可信维度只有 2 个。

### D3. API 推送通道下 origin ref 是「内容等价代理」，非真实远端 sha
`commit-push.js` 注释自承：Git Data API 建的 commit sha 与本地不同，于是把 `refs/remotes/origin/<branch>` 写成**本地 HEAD**。后果：`git status`/`git log origin` 显示的远端状态是假的（sha 对不上），ahead/behind 判断依赖 tree 比较绕开。属于已知取舍，但应在 README 显眼声明，且 autoTag 指向的是远端 API commit、与本地历史永久分叉。

### D4. 推送许可触发面过宽 + 作用域默认 all
`permit.js` 触发条件 = 回复含 `✅`（含「✅ 已解答」这种闲聊级标记）；`pushScope` 默认 `all` = 把工作区**所有**有变更的仓库都提交推送。默认关闭兜住了风险，但一旦打开，误推面极大。建议：触发器改严格（要求 ✅ + 「任务完成」同行）、scope 默认 `session`。

### D5. token 探测面过宽 = 泄露面过宽
`resolveGitToken` 会扫 `HOME/DSH_HOME` 下「会话/sessions/workspace」目录的**每个子目录**找 `.git-push-token`——任意目录里落一个 token 文件就会被静默征用，既难审计来源也扩大暴露面。`_tokenValidCache` 60s 缓存意味着 token 撤销后最多 60s 仍被当有效。

### D6. /tmp known_hosts 每进程一个、永不清理
`pushViaSsh`/`probeSshGithubAuth` 用 `dsh-git-push-known-hosts-${process.pid}`，长期运行 /tmp 堆积小文件；且 `accept-new` 对 key 变更场景直接失败无提示。

### D7. `cp -a` 与自家 CIFS 经验矛盾
`remote-repo.js:219` clone 落盘用 `cp -a`（保属性），而本项目 skill 体系明确「CIFS 上勿用 cp -a/rsync 保属性」——跨卷/EXDEV 场景会失败。应改 `cp -r` + 显式 chmod 兜底。

### D8. 规则集缓存键不含文件内容
`rule-packs.js` `_cache` 键 = `order|weights`，改了 YAML 规则文件本体但顺序/权重不变时，进程内仍吃旧缓存（需重启/清缓存生效）。对「规则文件即权重文件」的卖点是体验缺口。

### D9. applyWeightOverrides 用 `re.source` 匹配 pattern
正则原文 ↔ source 的对应在含转义/flags 时有歧义（如 `a\/b` vs `a/b`），权重覆盖可能静默不命中。

### D10. permit 状态 Map 无界增长
`permitLastTurns`/`permitTimers` 按 sessionId 累积，常驻实例会话多了以后缓慢涨内存。应加 LRU 或按天上限清理。

### D11. client.js 1010 行手写 `jsx.jsxs(...)` 调用 + CSS 字符串拼接
无 JSX 编译、无组件文件拆分，改 UI 的心智成本和维护风险都高；l18n 文案 zh/en 两份平铺，加第三语言即失控。

### D12. 审计的「无变更短路」几乎跳过一切
`auditRepo` 在 `fileList.length === 0` 时只跑私密文件存量检查就返回 0 findings——本次自审 0 blocker 就是这么来的。git 干净 ≠ 代码没问题，报告里应如实写「未审」，现在写的是 `passed: true`。

## 四、工程化缺口

- **无 lint / formatter / CI**：风格全靠自律；`node --check` 只查 11 个文件（lib 有 27 个）。
- **测试集中度高**：36 个测试大头在规则引擎/审计；github-api、remote-repo、version-history、client 几乎无测试覆盖。
- **README 66KB 单文件**：版本表与正文混排，已超出人读友好范围；docs/ 下堆积 10+ 份历史分析报告无归档目录。
- **package.json scripts.check 清单手维护**：新增 lib 文件（如 rule-packs.js 之后的模块）不在 check 列表里。
