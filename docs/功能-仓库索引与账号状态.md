# 功能：仓库索引与账号状态

> 面向使用者：讲清「侧边栏那两个状态（仓库列表 / 凭据状态）的数据从哪来、什么时候刷新、怎么排查」。

## 一句话

插件维护两份落盘数据——`dsh-repo-index.json`（工作区仓库索引）与 `account-status.json`（凭据校验快照）——并规定**唯一的写入时机与读取入口**，避免多处各写一份导致状态打架。

## 一、仓库索引（`dsh-repo-index.json`）

**是什么**：扫描工作区里的 git 仓库（含嵌套 `.git`），记录分支 / remote / 未提交数 / 未推送数 / 最近活动等，供侧边栏列表与 `git_scan` 使用。

**怎么更新**：

| 触发 | 行为 |
|------|------|
| `git_scan` / 侧边栏刷新 | 扫描并回写索引 |
| 推送成功后 | 串行两步：先**全量重建**（`mode: rebuild`），再按本次结果**精确回写**（避免全量扫描太慢时状态滞后） |
| 扫描进行中 | 通过 `scan-live.json` 暴露进度（`scan-runner`），索引写入走原子写 |

**相关实现**：`lib/git/repos.js`（扫描）、`lib/git/repo-index.js`（索引维护）、`lib/git/scan-runner.js`（进度）、`lib/git/atomic-json.js`（原子写，防写一半被读到）。

## 二、账号状态（`account-status.json`）

**是什么**：token 与 SSH 公钥的有效性快照（各自 `valid` / `login` / `checkedAt` / `timeout`）+ API 通道配额，供设置侧边栏的凭据块展示。

**写入时机（关键）**：

- **每次推送/提交验证账号时刷新** —— 即推送成功后顺带校验并回写（`refreshAccountStatus`）；
- **设置侧边栏打开时只读**，不触发在线校验。

所以「校验于 <时间>」停在很久以前，通常意味着**此后没有成功的推送**，而不是功能坏了。想让时间刷新，点侧边栏的「重新检测」，或成功推送一次。

**配额后缀**：Token 行尾的「（配额剩余 N/h）」来自 GitHub 的 `GET /rate_limit`（不消耗配额），打开页面时按后端缓存刷新（60 秒缓存，`?refresh=1` 强制）。

**相关实现**：`lib/git/account-status.js`（写入与读取的唯一收口）、`lib/git/account.js` / `lib/git/api.js`（在线校验与响应头解析）。

## 三、为什么强调「统一收口」

同一份状态若允许多处写，就会出现「A 处写了 B 处不知道」「UI 读到的还是旧值」。本插件的约定是：

- **写**：只有收口函数能写（账号状态走 `writeAccountStatusFromResult` / `updateAccountStatusQuota`；索引走索引维护模块）。
- **读**：设置侧边栏走 HTTP（`settings-get` / `account-status`），不走 client 侧快照——反代访问时 client scope 快照恒为 memory 模式，用它判断「可用/可写」会导致整页空白。
- **回执**：写接口返回 `statusUpdated` 之类的标记，UI 据此决定是否重新读取，避免「写了但界面没变」。

## 边界与注意

- 两份数据都在插件配置目录（`<DSH_HOME>/git-push/`），**不要手工改**（有格式与原子写约定）。
- 索引扫描尊重 `.gitignore`：被忽略的目录整棵跳过（可在审计里用 `--include-ignored` 显式包含）。
- 凭据文件（token / SSH 私钥）与这两份**状态文件**是两回事：前者是凭据真源，后者只是校验结果快照；「是否已配置」一律查凭据真源，不看快照。
