# 提交前预处理与审计引擎解耦方案（2026-11-13）

> 状态：**设计稿（待实施）**。目标是把「提交前审计」从写死的代码动作，改成**调用可配置的审计引擎**，
> 并为审计 UI 定义注入契约。收益：换审计引擎（含换语言重写）时 git 侧零改动；
> 审计 UI 可插拔，不绑定任何一个引擎的实现细节。
>
> 约束：**不影响现有使用行为**——默认配置下判定结果、拦截语义、回显文案逐条一致。

## 一、现状（实测）

### 1.1 耦合点集中在 runAudit

```
lib/commit-push.js  runAudit()   93 行，提交门禁的唯一实现
  ├─ import auditWithScope      审计内核（真正的「引擎」）
  ├─ import scoreQuality        评分
  ├─ import buildAuditApiGuide  输出文案（纯本地派生）
  ├─ import isSampleExemptDir   示例目录豁免（依赖 repo 语义）
  └─ resolveRepoVisibility()    查 GitHub 可见性（网络 + token，git 侧能力）
调用方仅 2 处：
  lib/app/tool-call.js:403      git_commit_push 工具
  lib/commit-push.js:152        commitWithAudit（CLI commit 走它）
```

**判断**：真正属于「审计引擎」的只有 `auditWithScope` + `scoreQuality`。
其余三项依赖 git 侧能力（repo 语义、网络、凭据），应留在 git 侧——这是解耦的正确切面。

### 1.2 现有 CLI 契约已够用，但加载代价高

`cli.mjs audit --json` 输出：

```json
{ "ok": true, "scope": "changed",
  "summary": { "blocker": 0, "warning": 2, "notice": 2, "total": 4 },
  "quality": { "dims": {}, "score": 96.28, "level": "A" },
  "findings": [ { "file": "", "line": 0, "rule": "", "severity": "", "message": "" } ],
  "files": 0 }
```

门禁所需字段齐全。两个缺口：

| 缺口 | 影响 |
|---|---|
| `--json` 模式恒返回退出码 0 | 门禁无法用退出码表达「有 blocker」，被迫解析 JSON 猜语义 |
| 无「只取 blocker」选项 | 大仓 findings 可达 4900 条（约 3.8MB），每次都全量传输 |

### 1.3 性能实测（同仓库同 scope，CIFS 挂载）

| 方式 | 耗时 | 说明 |
|---|---|---|
| 进程内 `auditWithScope`（现状） | **1.0s** | 当前提交门禁开销 |
| 重量级 CLI `cli.mjs audit --json` | **6.4s** | CPU profile：2.0s ESM 解析 + 1.5s `openSync` + 1.0s 模块编译 |
| **专用轻量入口**（只加载 audit+score） | **1.3s** | 子进程 + JSON stdout，比进程内仅多 0.3s |
| 纯 node 启动（基线） | 0.2s | — |

**结论**：直接调 `cli.mjs audit` 会引入 5.4 秒无谓开销（全是 `cli.mjs` 全家桶的模块解析）。
必须提供**专用轻量入口**——这是本方案可行性的关键前提。

## 二、设计：审计引擎契约（配置化入口）

### 2.1 入口完全配置化（支持换语言重写）

```jsonc
// config.json —— 缺省不写 = 内置默认，行为不变
"preCommit": {
  "command": "",        // 空 = 内置默认（当前 node 解释器）
  "args": [],           // 空 = 内置默认（<pluginRoot>/scripts/audit-gate.mjs）
  "timeoutMs": 600000
}
```

**调用形态**（`--repo/--scope/--json` 由插件追加，引擎只需解析）：

```
<command> <args...> --repo <绝对路径> --scope diff|full [--ruleset <dir>] [--weights <json>] --json
```

换引擎只需改配置：

| 场景 | command | args |
|---|---|---|
| 内置（默认） | 空 | 空 |
| Python 重写 | `python3` | `["tools/audit_gate.py"]` |
| Go / Rust 二进制 | `/opt/audit/bin/audit-gate` | `[]` |
| 附加调试参数 | `node` | `["my-engine.mjs", "--timing"]` |

**路径解析规则**：`args` 里的相对路径相对**插件根**解析（可预测、换机不断链）；绝对路径原样；
`command` 走 PATH 自探测（找不到要显式报错，不静默降级）。

### 2.2 契约内容（与语言无关）

```
stdout : 单行 JSON { ok, scope, summary:{blocker,warning,notice,total},
                     quality:{score,level}, findings:[...], files }
退出码 : 0 = 无 blocker（放行）
         1 = 有 blocker（拦截）
         2 = 执行失败（引擎崩/参数错/内部错误）
stderr : 仅诊断信息，不参与判定
超时   : 达到 timeoutMs 一律按「执行失败」处理
可选   : --blockers-only 时 findings 只含 blocker 级（门禁路径用，避免大仓全量传输）
```

**为什么用退出码而不是解析 JSON 猜**：语义明确、任何语言都能实现（`exit 0/1/2`），
且「引擎崩溃」与「审计不通过」是两种完全不同的结局，不能混。

### 2.3 职责切分

| 职责 | 归属 | 理由 |
|---|---|---|
| 产出 findings / summary / quality | **审计引擎** | 可替换部分 |
| 示例目录豁免（`isSampleExemptDir`） | git 侧 | 依赖 repo 目录语义 |
| 临时豁免文件（`auditExemptPaths`） | git 侧 | 调用方参数，非引擎概念 |
| 私有库豁免（`resolveRepoVisibility`） | git 侧 | 依赖 GitHub 网络与 token |
| `blocked` 摘要、`apiGuide` 文案 | git 侧 | 纯本地派生 |
| **拦截判定** | git 侧 | 拿引擎结果 + 自己的豁免规则后判 |

### 2.4 失败语义：fail-closed

引擎不可用（崩溃 / 超时 / 退出码 2 / stdout 无法解析）⇒ **拒绝提交并明确报错**：

```
提交前预处理失败：引擎 <command> <args> 退出码 2
  stderr: <尾部 2000 字符>
  （未执行任何 git 操作；修复引擎或临时关闭 auditEnabled 后重试）
```

与现状一致：当前审计抛异常会向上冒泡导致工具调用失败，本设计只是把「异常」换成「明确分类的错误」。

## 三、设计：审计 UI 注入契约

> 参考 `dsh-model-team` 的 `ui/theme-sdk` 范式（2026-11-13 实地考察）：
> **契约单独成文件（版本 + 类型 + define 校验）→ 唯一导出面 → 实现 → 构建期校验**。

### 3.1 为什么 UI 也要契约化

`2.20.15` 已把审计 Tab 移出构建（分片归档在 `lib/client-parts/audit/`）。若不定义契约，
将来接回来仍是「写死的一个 Tab 组件」——换引擎后 UI 与引擎的数据结构强耦合，等于没解耦。

### 3.2 契约要素（照 theme-sdk 四件套）

```js
// lib/audit-ui-sdk/contract.js —— 只有类型/常量/校验函数，不含实现
export const AUDIT_UI_CONTRACT_VERSION = 1;

/** 面板必须满足的形状；校验在**构建期**做，运行期不重复 */
export function defineAuditPanel(definition) { /* 校验 meta / Panel / 版本 */ }

// meta      : { id, name, contractVersion }   id 形如 /^[a-z][a-z0-9-]{1,31}$/
// Panel     : (props) => vnode                替代现有 dshgp_AuditTab
// props     : {
//   data    : { summary, quality, findings, ruleSlots },   // 引擎返回的只读数据
//   actions : { reload, toggleRule, editWeight, toggleDisabled },
//   state   : { loading, error, auditEnabled, auditScanScope },
// }
// styles?   : string      自带 CSS 文本（构建期收进产物，不引外部文件）
// setup?    : (ctx) => void | (() => void)   卸载清理
```

### 3.3 三个硬约束

1. **唯一导出面**：实现只能从 `lib/audit-ui-sdk` 这一个入口 import。绕过它去 import 内部文件，
   SDK 重构就会伤到别人（theme-sdk 的 `index.ts` 注释明确写了这条）。
2. **构建期校验**：坏实现要在打包时被挡，而不是等宿主里报错。校验项**只覆盖构建期一定能判的部分**
   （形状与版本），不猜作者意图——猜意图的校验会在真实实现上误报，最后逼人关掉校验。
3. **契约版本**：破坏性改动 `+1`，构建期拒绝按旧契约写的实现。

### 3.4 本阶段范围（不重做 UI）

| 做 | 不做 |
|---|---|
| 定义 `lib/audit-ui-sdk/`（契约 + 校验 + 唯一导出面） | 不实现新审计 UI |
| 把现有 `client-parts/audit/audit.js` 视作「默认实现」的参考，**不改动它** | 不把审计 Tab 接回构建 |
| 在 SPEC 写明「将来接回时按契约实现」 | 不动 `client-parts/git/` 的页面装配 |

## 五、兼容性（三条保证）

1. `auditEnabled=false` → 完全不调用（与现状一致）
2. `auditEnabled=true` + 默认 `preCommit`（空配置） → 判定结果、拦截语义、回显文案**逐条一致**
   （同一个 `auditWithScope` + `scoreQuality`，只是搬到子进程跑）
3. 新配置项缺省 = 内置，**老 `config.json` 无需迁移**

## 六、风险与边界

| 风险 | 程度 | 缓解 |
|---|---|---|
| 每次提交多 0.3s（CIFS） | 低 | 轻量入口实测 1.3s；大仓审计本身 10s+，占比 <5% |
| findings 全量传输（大仓 3.8MB） | 中 | 门禁路径用 `--blockers-only` |
| **无进程内退路**（只留子进程） | 中 | 契约测试必须自证「引擎挂=拦得住」；错误信息带命令/退出码/stderr |
| 引擎崩溃的调试链变长 | 中 | stderr 落 job 输出；超时与退出码分类报错 |
| 退出码语义被误实现 | 中 | 契约测试用假引擎覆盖 0/1/2 三种退出码 |

**明确不做**：不改 `auditWithScope` 的行为；不改规则与评分；不动 `client-parts/git/` 的页面装配。

## 七、落地顺序（分阶段，每阶段可独立验证）

```
阶段 1  新增 scripts/audit-gate.mjs + 契约测试（不改任何现有调用路径）
        └─ 验证：与进程内 auditWithScope 同仓库比对，findings/summary/quality 完全一致
阶段 2  新增 lib/commit-push/pre-commit-engine.js（spawn + 解析 + 错误分类）
        └─ 验证：假引擎覆盖退出码 0/1/2 + 超时
阶段 3  runAudit 切到引擎调用；schema 加 preCommit 配置
        └─ 验证：全量回归；手工比对提交门禁行为（blocker 拦截、私有库豁免、临时豁免）
阶段 4  新增 lib/audit-ui-sdk/（契约 + 唯一导出面 + 构建期校验）
        └─ 验证：契约测试（坏实现被拒、版本不匹配被拒）
阶段 5  文档：SPEC 两节 + 本方案归档为「已实施」
```

## 八、验收标准

1. 默认配置下，对同一仓库同一改动：`blocked` 列表、`summary`、`quality.score` 与改造前**逐条一致**
2. 人为造 blocker → 提交被拦，错误信息含「引擎命令 + 退出码 + 拦截条数」
3. 把 `preCommit.command` 指向不存在的程序 → 提交被拦（fail-closed），错误信息指明「找不到命令」
4. 把 `preCommit.command` 指向一个立刻退出的假引擎 → 按退出码正确分类（0 放行 / 1 拦 / 2 失败）
5. UI 契约：按契约写的实现通过构建期校验；写错 meta.id 或版本不匹配 → 构建失败并给出字段名
