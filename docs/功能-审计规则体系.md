# 功能：审计规则体系

> 本文面向使用者，讲清「审计检查什么、怎么配置、怎么看结果、怎么豁免」。
> 规则以 yml 声明，落地在 `lib/audit-rules/`，实现分布在 `lib/ast/`（判定）与 `lib/checks/`（产出 finding）。

## 一句话

对仓库做静态审计：**21 个规则槽位 / 122 条规则**覆盖语法、敏感信息、可读性、健壮性、性能、文档等维度，输出可分级（拦截 / 警告 / 提示）、可评分（0-100 + 等级）、可豁免的结果。

## 规则怎么组织

### 槽位（按语言与领域分）

`lib/audit-rules/audit-rules-<槽位>.yml`，当前 21 个槽位：

```
comment  cpp  docs  dsh  filehealth  folder  frontend  go  i18n  java
nodejs  npm  performance  php  private  python  robustness  rust
structure  swift  template
```

- **语言槽位**（`java` / `python` / `go` / `rust` / `swift` / `cpp` / `php` / `frontend` / `nodejs`）只作用于对应扩展名（如 python 槽位 `exts: ["py"]`）。
- **领域槽位**：`private`（私密文件拦截）、`folder`（目录结构）、`structure`（循环依赖）、`performance`、`i18n`、`docs`、`comment`、`npm`、`dsh`（DSH 插件契约）、`filehealth`、`robustness`。
- **`template`**：规则模板（新增规则照它写）。

### 规则的作用域字段

写规则时最容易漏、也最容易误报的是「作用域」——`lib/checks/filter.js` 是唯一落地点：

| 字段 | 语义 | 典型用途 |
|------|------|----------|
| `exts` | 扩展名白名单 | 只对某类文件跑 |
| `include_paths` | **路径白名单**：不含 `/` 按**文件名**匹配（任意层级）；含 `/` 按路径相等/前缀/后缀 | 只对 `package.json` 跑 |
| `exclude_paths` | 路径黑名单（前缀） | 排除 `server/`、`test/` |
| `file_patterns` | **文件内容**初筛正则（不是路径！） | 只在正文含某特征时才做重检查 |

为什么要有 `include_paths`：`exts` 只能收到**扩展名级**，而 `.json` 是跨语种通用格式（npm 的 `package.json`、Live2D 的 `model.json` 都是 json）。`npm/version-format-triple` 原先只有 `exts: ["json"]`，把规则套到了所有 json，第三方资源仓库（实测 0 个 package.json）被报 1435 条 error；加 `include_paths: ["package.json"]` 后只对真正的 package.json 生效。

### 规则字段速查

```yaml
- id: 槽位/规则名            # 全局唯一，形如 readability/variable-min-length
  name: 人类可读标题
  category: 分类
  severity: blocker|warning|info   # 展示级别
  description: 这条规则查什么、为什么
  exts: ["js", "mjs"]        # 作用域（见上表）
  patterns: ["正则"]          # 正则初筛
  astConfirm: true           # 需要 token 级精筛（剔除注释/字符串里的假命中）
  astConfirmKind: io-risk    # 精筛器名字（lib/ast/* 实现）
  min_length / threshold / max_lines: 数值参数（各规则自定）
  exceptions: ["i", "j"]     # 名字类规则的允许名单
  fixable: true|false        # 是否给出修法
  external: <扩展脚本名>      # 交给 scripts/audit-ext/<名>.mjs 执行（内置链停跑）
  dimensions: ["性能", "健壮性"]  # 归属评分维度（不声明会落到默认维度，导致评分失真）
```

## 三层结构（为什么规则这么写）

```
① 规则声明   lib/audit-rules/*.yml        只声明「查什么」，不含判定逻辑
② 判定实现   lib/ast/*                     token 级判定（返回「应报的行号集合」）
③ 检查器包装 lib/checks/*                  把判定转成 finding（补 message/维度/豁免提示）
④ 编排调度   lib/audit/*                   收集文件 → 按 kind 调度 → 汇总评分
```

新增一条规则的最小路径：yml 加条目 → 需要精筛就写 `lib/ast/*` → 在 `lib/checks/common.js` 接线 → 跑测试。

## 运行方式

三种入口（同一套规则与评分）：

```bash
# ① 插件工具（AI 会话里）
code_audit  repo=<仓库绝对路径>  scope=full|diff  ruleset=<自定规则目录>  weights=<JSON>

# ② CLI
git-sluice audit <仓库> [--full] [--ruleset <目录>] [--weights <JSON>] [--include-ignored]
                       [--history [--since <提交>] [--until <提交>] [--out <目录>]]

# ③ HTTP（设置侧边栏 / 外部脚本）
curl 'http://<本机IP>:30800/api/git-push/audit?repo=<路径>&scope=full&groupBy=rule'
```

`groupBy` 可选 `rule|file|severity|slot`，用于按不同维度聚合命中。

## 结果怎么读

- **分级**：`blocker`（拦截提交）/ `warning` / `info`。提交推送时 blocker 会拦住（除非该仓库是 private —— 见下）。
- **评分**：10 个维度加权（可读性 15 / 可维护性 15 / 健壮性 15 / 安全性 18 / 性能 10 / 测试覆盖 10 / 可观测性 5 / 可部署性 5 / 文档 4 / 开发者体验 3），得 0-100 分与等级（A/B/…）。
- **私有库豁免**：GitHub 可见性为 private 时，私密文件与工作留痕类只提示不拦截（private 边界内可正常提交）；public 才拦截。
- **低风险项不计分**：如 `robustness/io-risk` 里「启动路径上的一次性同步 I/O」按低风险展示但 `scoreImpact: 0`，不拉低评分。

## 怎么豁免

在文件头（前 3 行）或行尾写注释标记，`lib/exempt/index.js` 是唯一判定入口：

| 标记 | 覆盖什么 | 写哪里 |
|------|----------|--------|
| `dsh-skip-sensitive` | 敏感类（凭据/密钥/私密路径等） | 文件头=整文件；行尾=本行 |
| `dsh-skip-quality` | 质量类（函数长度/空 catch/同步 fs/魔数/措辞/注释密度/文件健康度） | 文件头 |
| `dsh-skip-func-length` | 单函数长度 | 文件头=全文件；函数定义行行尾=单函数 |
| `dsh-skip-complexity` | 圈复杂度（单一职责但天然多分支的函数） | 函数定义行行尾 |
| `dsh-skip-size` | 文件体积 | 文件头 |
| `dsh-skip-syntax` | 语法/解析类 | 文件头 |
| `dsh-skip-residue` | 残留类（debugger/todo/console/单行 I/O） | 行尾 |
| `dsh-skip-style` | 数值风格类（短名/行数/复杂度阈值等） | 文件头 |
| `dsh-skip-i18n` | 国际化类 | 文件头 |

**关键**：finding 里的 `exemptHint` 会告诉你该用哪个标记（按规则名前缀自动选，与实际生效的标记一致）。写了不生效的标记不会豁免——提示与行为保证一致。

## 设计原则（踩过坑后固化）

1. **自家纪律不要固化成审计规则**：审计规则对任何仓库生效，而「一次提交=一个小版本」这类只适用于本机自研项目的纪律写进规则，必然在第三方仓库大面积误报。这类约定放 skill。
2. **首 token 判不了内容的规则不报**：`duplicate-constant` 只比较「名字 + `=` 后第一个 token」，因此对象/数组字面量、`new Set(...)` 一律跳过（实测 `WRITE_METHODS` 在 `lib/ast` 是数组方法、在 `lib/http` 是 HTTP 方法，仅名字撞车）；独立脚本与 `lib` 的同名常量也不报（脚本要能单独运行）。
3. **提示词必须与实际行为一致**：`exemptHint` 提示的标记，写下去必须真能豁免——曾经出现「提示 residue 但 residue 不覆盖该 kind」导致提示形同虚设。
