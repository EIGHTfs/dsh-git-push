# dsh-git-push 2.9.0 设计稿：审计引擎的查询式演进（正则作为回退）

> **状态：设计稿，未实现。** 本文只记录目标形态与**预估**改动清单，不产生代码改动。
> 文中所有「预估」均为**估算**（未实测），实现时以实测为准。
> 前置已完成：2.8.9 的列级精筛（`astConfirmSpan`）与 `assets/tree-sitter/` 试点资产落库。

## 1. 目标与边界

**一句话目标**：把审计引擎从「正则匹配文本」演进为「**语法树查询为主、正则作为回退**」，
让规则判定不再依赖文本形状，从而同时提升**准确度**（消灭注释/字符串类误报）与**覆盖能力**
（表达结构关系：如「循环体内的 await」「函数参数里的硬编码值」）。

**验收标准**（2.9.0 达成时）：
1. 有语法的语言：规则命中由**语法节点**确认（同一批样本上，误报数不高于 2.8.9，且真阳性零回退）；
2. 无语法/加载失败/超预算：**自动回退**到 2.8.9 的 token 级判定，行为与 2.8.9 逐条一致；
3. 全量测试 + 门禁四项全绿；`npm pack` 体积在预算内（见 §6）。

**不做什么**：不改 CLI/工具/HTTP 面；不一次性重写 22 个规则包；不引入 native 依赖（只 WASM）。

## 3. 目标形态

```
一个文件进来
  ├─ ① 语言判定（detectLang / 扩展名）→ 是否有可用语法？
  │     ├─ 有 ⇒ ② 解析成语法树（内容 hash 缓存）
  │     │        ├─ 规则命中处 → descendantForPosition 取节点 → 节点/祖先是否 string|comment|template？
  │     │        │     ├─ 是 ⇒ 丢弃该命中（不是真代码）
  │     │        │     └─ 否 ⇒ 确认命中（真代码）→ 交给现有 finding 组装
  │     │        └─ 解析有语法错误（hasError）⇒ **放弃本文件**，落回 ③（保守策略）
  │     └─ 无 ⇒ ③
  └─ ③ 回退：2.8.9 的 token 级判定（行级 + 列级）——行为与 2.8.9 一致
```

关键点：**回退不是异常路径，而是常态路径之一**（无语法、解析失败、超预算、wasm 缺失都走它）。

## 4. 预估改动清单

| # | 文件/模块 | 改动 | 预估工作量 | 风险 |
|---|---|---|---|---|
| 1 | `lib/ast/treesitter.js`（新增） | 懒加载 `web-tree-sitter`（ESM ✓）+ 语法 wasm；语言→语法映射；`Parser`/`Language` 缓存；`confirmHits(text, lang, hits)`；`resetTreeSitterCache()` | 中（约 150~250 行） | 加载失败必须不影响审计（全部 try/catch + 回退） |
| 2 | `lib/checks/regex.js` | 在 `astConfirmSpan === true` 分支内优先走语法确认；拿不到语法/解析失败 ⇒ 走 2.8.9 的列级判定 | 小（约 30 行） | 不能改变无语法语言的既有结果 |
| 3 | `lib/rule/registry.js` | 新字段/新 kind 继续登记 `withRuleScope`（若新增 `astConfirmKind: 'tree-sitter'` 则登记之） | 极小（约 5 行） | 漏登记 ⇒ **单测绿、生产静默失效**（2.8.9 已踩过 ✗） |
| 4 | `lib/ast/lang.js` | 语言名与语法名的规范化映射（js/mjs/cjs/jsx→javascript；ts/tsx/mts/cts→typescript；py→python） | 小 | 映射错 ⇒ 加载不到语法（走回退，不致命） |

| 6 | `test/test-treesitter.mjs`（新增） | ① 语法路径：字符串/注释内命中被丢弃、真代码保留；② **回退路径**：把 assets 指到不存在目录 ⇒ 结果必须与 2.8.9 一致；③ 解析失败文件（故意写坏）⇒ 回退 | 中 | 测试里必须**双向**（只测语法路径会漏掉回退回归） |
| 7 | `scripts/sync-plugin.mjs` / `package.json` | 已含 assets（2.8.9 完成 ✓）；确认 `npm pack` 清单含 wasm | 极小 | 漏发 ⇒ 装机后永远走回退（功能静默降级 ✗） |
| 8 | `docs/`（本文） | 2.9.0 实现后回填「实测体积/命中集对比/回退一致性证据」 | 小 | 文档与实现分叉（用 `doc-*` 门禁钉住可计数项） |

**规则迁移（阶段 3，单独排期，预估工作量最大）**：

| 优先 | 规则族 | 为什么优先 | 预估 |
|---|---|---|---|
| ① | 安全类（eval / 凭据 / 危险调用） | 误报代价最高；语法确认收益最直接 | 每条 0.5~1 人时 + 双向回归 |
| ② | 性能类（循环内全量物化 / 重复调用 / 忙等待） | 结构关系（"在循环体内"）用正则表达脆弱 | 同上 |
| ③ | 结构类（函数长度/嵌套/复杂度） | 已有自研实现且较准 ⇒ **可不动** ✗ | —— |

## 5. 分阶段与验收

```
阶段 2（进行中）：C 接线 —— 语法树只做「命中处是否真代码」确认（等价替换列级判定）
                验收：误报数不升、真阳性零回退、无语法语言结果与 2.8.9 逐条一致
阶段 3：查询式规则 kind —— 新增 astConfirmKind: 'tree-sitter'（或 .scm 查询文件），
        只用于**新规则**与**迁移的高价值规则**（不改旧规则格式）
阶段 4：默认反转 —— 有语法且预算内 ⇒ 查询式为主；否则正则回退（本文 §3 的形态）
```

## 6. 体积与性能预算（**预估** ⚠️）

```
体积：现在整包 ~950KB；试点 3 语言后 ~4.4MB ✓（实测）；补齐 9 语言预估 ~11~13MB ⚠️
      ⇒ 备选：语法按需分发（首个使用某语言的仓库才提示下载）✗ 但破坏"装完即用"，需你定
性能：解析成本 ≈ O(文件大小)，实测未做 ⇒ 预估单文件 1~10ms（1KB~100KB 量级）⚠️
      缓解：① 只解析**有语法**且**正则已命中**的文件 ② 内容 hash 缓存 ③ 单文件大小上限
      ④ 超时预算（如单文件 > 200ms 即放弃解析、走回退）
```

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| wasm 加载失败/被杀软拦 | 全部包 try/catch ⇒ 回退 token 级；启动日志留痕 |
| 解析比正则慢 ⇒ 审计变慢 | 只在「已命中候选」上解析 + 缓存 + 大小/超时预算 |
| **新字段被 withRuleScope 丢弃**（2.8.9 已踩 ✗） | 新增字段必须同时改：规则 yml + 编译器透传 + withRuleScope 登记 + 双向测试 |
| 空占位包的语法无人验证 | 语法加载自检（能 load + 能 parse 空文件）纳入测试 |
| 体积膨胀 | §6 预算；必要时改「按需下载」并同步改 README 口径 |

## 8. 待确认项

1. **体积上限**：9 语言 ~11~13MB 是否接受？（不接受 ⇒ 改按需下载，或只保留 js/ts/python）
2. **frontend 包是否要 css/html 语法**（其规则覆盖 css/html）⇒ 需要则再加 2 个语法。
3. **阶段 3 是否引入 `.scm` 查询文件**（规则从 yml 表达式变为查询文件）——影响规则包组织方式。
4. 2.9.0 是否**必须**包含阶段 4（默认反转），还是阶段 2/3 完成即可发 2.9.0。
