# 功能：历史提交审计

> 面向使用者：讲清「为什么需要、怎么跑、输出什么、和普通审计的区别」。

## 一句话

普通审计只看**当前文件**（工作区快照）；历史提交审计把规则**逐条提交回放**，找出「历史上提交过、现在可能已被删掉或改掉」的问题——用于给老仓库做体检、或回答「这个问题是什么时候引入的」。

## 解决什么

- 当前快照干净，不代表历史干净：密钥曾提交过、后来删了，git 历史里仍在。
- 想知道某条规则命中是**从哪次提交开始**出现的。
- 想按时间段抽查（例如「最近 20 次提交有没有引入敏感信息」）。

## 怎么跑

```bash
# CLI（推荐）
git-sluice audit <仓库> --history                          # 全部提交
git-sluice audit <仓库> --history --since <提交>            # 从某提交起
git-sluice audit <仓库> --history --until <提交>            # 到某提交止
git-sluice audit <仓库> --history --out <目录>              # 报告落盘目录
```

也可以在插件工具里用 `code_audit` 传 `history: true`（参数同上）。

## 输出

- 逐提交的结果（命中规则 / 文件 / 行 / 消息），以及**报告文件**（`--out` 指定目录）。
- 实现分两块：`lib/audit/history.js`（逐提交回放与调度）、`lib/audit/history-report.js`（报告生成）。

## 与普通审计的差异

| 维度 | 普通审计（diff / full） | 历史提交审计（history） |
|------|------------------------|------------------------|
| 输入 | 当前工作区文件（diff=变动文件，full=全量） | 每个提交的快照 |
| 用途 | 提交前门禁 / 体检当前状态 | 回溯老仓库、定位问题引入点 |
| 成本 | 低（按文件） | 高（按提交 × 文件），大仓库慎用 `--full` 组合 |
| 拦截 | 参与提交门禁 | 只出报告，不拦提交 |

## 边界与注意

- 逐提交回放是**只读**操作，不改动仓库。
- 提交很多时耗时线性增长；建议用 `--since/--until` 收窄范围。
- 报告是快照，不会自动更新；需要最新结果就重跑。
