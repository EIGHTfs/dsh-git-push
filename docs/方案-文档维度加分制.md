# 方案：文档维度改纯加分制（0 分起、上限 10、不冲突现有 yml 规则）

> 状态：方案草案（未改代码），待用户确认后按看板执行。
> 来源：`DeepSeekHarness/文档加分制.md` 讨论（EIGHTfs：文档基本满分没被扣，改 0 分加分制，上限等同扣分制满分；只奖励结构信号与交叉验证，不判断内容质量）。
> 版本：未定（实现时确认是否升版）。

## 一、修改目标

- **问题**：文档维度（权重 4/100）在扣分制下几乎不扣分——docs 槽位只有 link-check 一条规则，所有项目文档维度≈满分，**4 分权重无区分度**（白拿分）。
- **期望**：文档维度改**纯加分制 0 分起**——`文档得分 = min(10, 命中项数 × 2.5)`；只奖励「做了」（结构信号 + 交叉验证），不判断「做得好」；上限锁死在文档维度内（权重 4 × 满分 10），不掩盖代码问题。
- **成功标准**：①4 项加分项机械可判、每项 2.5 分 ②加分范围=**文档集**（README + docs/ + 根级常见文档名），文档好得满分、缺失 0 分，区分度出现 ③**不冲突现有 yml 规则**（加分项不进扣分维度计数、不与 version/readme-changelog 等规则口径互踩）④判断不了项列「人工复核」不自动评分 ⑤全量测试回归通过。

## 二、现状实证（2026-09-21）

| 现状 | 位置 | 说明 |
|---|---|---|
| 评分公式 | `lib/score/index.js` | 10 维度扣分制：`dims[d]=max(0.1, 10-k·ln(1+count))`；文档 k=0.8、权重 4；`countByDimension` 按 finding.dimensions 计数（scoreImpact 0 不计） |
| 文档维度问题来源 | docs 槽位 | 仅 `link-check`（链接有效性，category documentation）——README 存在性/版本/命令/环境变量**无任何检查** → 文档维度恒满分 |
| 现有 README/版本规则 | `audit-rules-version.yml` | `version/readme-changelog`（README 缺版本记录 warning）、`readme-zero-title`（0.x 标题）、`changelog-many-entries`——查**版本记录表结构** |
| 现有文档相关 | `structure/tree-doc-drift`（README 目录树漂移）、comment 槽位多条（注释类 category documentation） | 与加分制判定面不重叠 |
| 加分先例 | `audit-rules-filehealth.yml` `base_score/warn_score/block_score` | 维度基础分机制可类比 |

## 三、潜在问题分析

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| **加分项污染扣分维度**（核心冲突） | 高 | 加分项若带 dimensions 进 findings → countByDimension 反向扣分（加分越多文档分越低） | 加分项**不进 findings**：单独 `auditResult.docsScore` 字段，scoreQuality 从 context 读；countByDimension 完全不受影响 |
| 与 `version/readme-changelog` 同源互踩 | 中 | 两处都读 README 版本，判据若重叠会既加又扣 | 口径错开：加分判「存在任一版本号 == pkg.version」（交叉验证）；changelog 判「版本记录表结构」——注释标注，防未来误并 |
| summarize/门禁语义污染 | 中 | 加分项混进 summary.total 被当「问题数」 | docs-score 不进 findings → summary/门禁零影响；报告单独「文档加分」段展示 |
| 无 README/非 git | 低 | 拿不到 README/pkg | hits=0 → 文档 0 分（合理）；异常静默返回 0 |
| 多文档口径不一致 | 中 | README 与 docs/CHANGELOG 版本号互相矛盾 | 提取文档集全部版本号：任一 == pkg 即加分（存在性）；去重后 >1 个不同版本 → 列「人工复核」提示，**不自动扣分**（不与 version 扣分规则冲突） |
| 文档集误收无关 md | 中 | node_modules/vendor/测试夹具的 md 被当项目文档 | 白名单圈法：README + docs/ 递归 + 根级常见命名；排除 .gitignore 忽略目录（复用审计收集器目录排除） |
| 版本号误匹配（README 提 Node 18.0.0） | 中 | 把无关版本当项目版本 | 判「任一 == pkg.version」（文档明确：不是全部一致），Node 18.0.0 ≠ pkg 版本不会误加 |
| 性能 | 低 | 每审计读 README+pkg（秒级） | 单次 readFileSync，可忽略 |

**边界条件**：
1. README.md 不存在 → hits 0（README 存在项本身 +0），文档 0 分。
2. package.json 不存在/JSON 解析失败 → 版本一致性项跳过（其余照判），不抛错。
3. 快照/历史审计场景（audit --history）：同逻辑对快照目录判（README 提取同源），无特殊处理。
4. 加分制**不改变**文档权重 4 与总分公式：`score = Σ(dims×w)/Σw×10` 原样，仅文档维度得分改加分制计算。

## 六、逐文件改动要点

### 6.1 `lib/score/docs-score.js`（新增，核心检查器）

- `collectDocFiles(root)`（**文档集圈法**，2026-09-21 讨论补）：`root/README.md`（约定入口，必查）+ `docs/**/*.md`（递归，排除 node_modules/vendor/test 等——复用审计收集器目录排除）+ 根级常见文档名白名单（CHANGELOG.md / INSTALL.md / GUIDE.md / UPGRADING.md / 升级记录.md / 快速开始.md 等）；无 docs/ 目录 → 文档集 = README（回退现状）
- `checkDocsScore(root)` → `{ hits: string[], review: string[], items: [{id,name,score,hit}], files: string[], versions: string[] }`
- 4 项（每项 2.5，检查范围=**文档集任一命中**）：
  1. **readme-exists**：`existsSync(root/README.md)`（README 是约定入口，docs/ 不能替代此项）
  2. **version-consistent**（交叉验证，最硬）：`JSON.parse(pkg).version`；文档集全文提取 `v?(\d+\.\d+\.\d+)` → **任一 == pkg.version** 才命中（Node 18.0.0 等无关版本不会误加）
  3. **install-command**：文档集匹配 `/npm install|pnpm add|yarn add|docker run|npm run (start|dev|build|serve)/i`
  4. **env-list**：文档集匹配 `/`.env|process`.env|环境变量/i` 或含「变量」的表格行
- `review`（不自动评分，进报告「人工复核」）：
  - README 完整性 / 版本是否最新 / 代码示例正确性 / 注释质量（静态判不了，诚实列出）
  - **文档集版本号不一致**（2026-09-21 讨论补）：提取全部文档版本号去重后 >1 个 → 提示「README=1.5.6 / docs/CHANGELOG.md=1.5.5 不一致，请人工核对」（存在性加分照给，矛盾只提示**不扣分**）
  - 无 README 只有 docs/ → 提示「README 缺失（docs/ 存在）」

### 6.2 `lib/score/index.js`

- `scoreQuality(findings, weights, { files, docsScore })`：
  - `const docHits = (docsScore?.hits?.length) || 0;`
  - 文档维度：`dims['文档'] = Math.min(10, docHits * 2.5)`（**替换**扣分制 `10 - 0.8·ln(1+count)`；counts['文档'] 恒 0 时原扣分制=10，新加分制=min(10,hits·2.5)）
  - 其余 9 维度不变（纯扣分制）；总分公式 `Σ(dims×w)/Σw×10` 不变 → 文档贡献 = dims['文档']×4（0~40 归一化前）
  - `emptyResult` 时（files=0）跳过加分制同现状

### 6.3 auditFull 组合

- auditFull 末尾：`const ds = checkDocsScore(root)` → `return { ..., docsScore: ds }`（**不 push 进 findings** → countByDimension/summarize/门禁零影响，天然不冲突）
- 注意：docs-score 在**仓库根**判（README/package.json 在根）；快照/子目录审计 root 即快照根，同逻辑

### 6.4 `audit-rules-docs.yml`

- 新增 `docs-score` 配置段（与 link-check 并列表述；loader 按 kind 分发）：
```yaml
- id: docs-score
  kind: docs-score
  name: "文档加分制（0 分起，上限 10）"
  category: "documentation"
  severity: "info"          # 加分项，非问题，不进扣分/门禁
  score_per_item: 2.5
  max_score: 10
  items:
    - id: readme-exists; name: "README 存在"; check: "existsSync(root/README.md)"
    - id: version-consistent; name: "版本号与 package.json 一致"; check: "README 任一 v?x.y.z == pkg.version"
    - id: install-command; name: "有安装/启动命令"; check: "/npm install|pnpm add|yarn add|docker run|npm run/"
    - id: env-list; name: "有环境变量清单"; check: "/\\.env|process\\.env|环境变量/"
  review: ["README 完整性", "版本是否最新", "代码示例正确性", "注释质量"]
```
- **冲突规避注释**：docs-score 的 version-consistent 与 version/readme-changelog 口径错开（一致性 vs 表结构），两规则可并存

### 6.5 报告展示

- `formatAuditBlock` / quality 输出附：`文档加分：命中 n/4（+x.x/10）` + `建议人工复核：…`（来自 docsScore.review）
